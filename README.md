# Sakuya

Локальная основа проекта для Windows 10/11: один BAT, сервер на свободном порту,
русское меню трея, данные отдельно от программы. Внешние Python-пакеты не нужны.

## Запуск

Распакуйте **весь проект** и дважды щёлкните `Sakuya.bat`. BAT можно запускать из
любой текущей папки и с другого диска. Поддерживаются пробелы, кириллица и `!`.
Папка проекта должна быть доступна для чтения; для локальной установки Python
и будущего обновления программы также нужна запись. Не запускайте файлы внутри ZIP.

| Команда | Поведение |
| --- | --- |
| `Sakuya.bat` | Проверка Python → сервер → проверка `/api/health` → трей → скрытие консоли и браузер |
| `Sakuya.bat -Mode diagnostic` | То же ядро, подробный журнал, консоль остаётся открытой |
| `Sakuya.bat -Mode quiet` | Подготовка видна, после готовности сервера и трея консоль скрывается |
| `Sakuya.bat -Startup enable` | Включить автозапуск текущего пользователя Windows |
| `Sakuya.bat -Startup disable` | Выключить автозапуск |

Повторный запуск открывает уже работающий экземпляр. При занятом порте сервер
выбирает другой и сообщает реальный адрес. На старт сервера отводится 15 секунд,
на подтверждение трея — 12, на ожидание другого запуска — 30.
Если трей не запустился или аварийно завершился, консоль остаётся/становится видимой:
управление сохраняется через **Ctrl+C**. При ошибке BAT ждёт нажатия клавиши.

В консоли используются значки: 🦊 🌸 ✦ — Sakuya, ⚙ — подготовка, ◈ — проверка Python,
↻ — загрузка и ожидание, ✓ — готовность, ⚠ — предупреждение, ✕ — ошибка.
Символы хранятся в UTF-8 ресурсах; BAT остаётся ASCII. Вид эмодзи зависит от шрифта консоли.

В интерактивной консоли активная строка заменяется результатом этапа: подготовка,
Python, экземпляр, версия и настройки, сервер, связь и трей. У каждого этапа
измеряется реальное время. Заголовок и адрес выделяются золотым, успешные этапы —
зелёным, предупреждения — жёлтым, ошибки — красным. После проверки связи и трея
выводится краткий итог: реальный адрес, режим и полное время запуска, включая
подготовку PowerShell. Обычный и тихий режимы скрывают консоль после этого итога.

При перенаправлении вывода управляющие последовательности не записываются;
диагностика выводит этапы отдельными строками и сохраняет подробный вывод.
Неудачный этап помечается красным, а блок ошибки содержит причину, конкретное
действие и путь к журналу. Например, повреждённый `settings.json` сопровождается
путём к файлу и описанием нужных полей. Полный traceback хранится в журнале
и выводится в консоль только при диагностике. Ни один этап не имитирует проценты.


Меню трея: **Открыть**, **Папка данных**, **Журнал**, **Выход**.
«Выход» останавливает HTTP-сервер, сохраняет настройки, убирает значок и освобождает
блокировку. ОС также освобождает блокировку после аварии: удалять lock-файл не нужно.

## Python и работа без интернета

Порядок поиска: `runtime/python/python.exe`, `python/python.exe`,
`.venv/Scripts/python.exe`, `py -3`, `python`, стандартные папки установки.
Каждый кандидат запускается настоящим процессом с тайм-аутом 10 секунд:
проверяются Python 3.11–3.15 и обязательные модули стандартной библиотеки.
Неработающий `python.exe` и псевдоним Microsoft Store не считаются готовым Python.
Неудачные проверки и отсутствующие модули записываются в `bootstrap.log`.

Если Python не найден, запуск предлагает локальную установку (ответ `Y` или `да`).
Закреплены **Python 3.14.9**, официальные URL и SHA-256 для x64, ARM64 и x86:
`config/python-runtime.json`. Хеши взяты из официального release manifest Python.org.
Загрузка идёт только с `https://www.python.org`, проверка SHA-256 предшествует
распаковке, распакованный интерпретатор проверяется **до** переноса в `runtime/python`.
Подготовка выполняется в уникальной временной папке на том же диске; при замене
старое окружение сохраняется до готовности нового. Незавершённый перенос
`python.previous` восстанавливается при следующем старте.

Исправный Python запускается без сети. Автоматической переустановки и `pip install`
при старте нет. В автозапуске установка Python не начинается без участия пользователя:
при отсутствии окружения показывается ошибка и путь к журналу.

## Данные и настройки

По умолчанию: `%LOCALAPPDATA%\Sakuya\`.

| Путь внутри папки данных | Назначение |
| --- | --- |
| `documents/` | Документы пользователя; программа запуска их не удаляет |
| `settings.json` | Настройки, записываемые атомарно |
| `logs/sakuya.log` | Журнал приложения, ротация 2 МБ × 5 файлов |
| `logs/bootstrap.log` | Подготовка Python и ошибки запуска |
| `logs/tray.log` | Ошибки трея |
| `run/` | Служебные сведения и блокировка экземпляра |

Пример `settings.json`:

```json
{
  "port": 0,
  "autostart_browser": false
}
```

`port: 0` поручает ОС выбрать порт. При необходимости задайте предпочитаемый номер.
`autostart_browser` управляет открытием браузера **только при входе в Windows**;
при обычном запуске браузер открывается. После изменения настроек перезапустите Sakuya.

Можно заранее задать абсолютный `SAKUYA_DATA_DIR`, чтобы выбрать другую папку данных.
Идентификатор экземпляра включает `aspksa.sakuya` и хеш абсолютной папки данных:
копии Sakuya с одной папкой данных используют один процесс, с разными — независимы.
Другие проекты должны иметь собственный `APP_ID`, папку данных и имя автозапуска.
Перенос программы не меняет стандартную папку данных.

## Автозапуск Windows

Включается явно командой выше, без прав администратора. Запись в `HKCU/.../Run`
содержит абсолютные пути к проверенному `pythonw.exe`, включённому в проект
`autostart.pyw` и папке данных. `.pyw` вызывает то же ядро через `scripts/start.ps1`.
По умолчанию браузер при входе в Windows не открывается. После переноса программы
или выбранного Python повторно выполните `Sakuya.bat -Startup enable`.

## Основа восстановления обновлений

Загрузчика обновлений с GitHub пока нет. Уже предусмотрен безопасный протокол
для следующего модуля: стабильный `bootstrap/` запускается до заменяемого `app/`.
Кандидаты размещаются в `releases/<id>/`; `active-release.json` указывает на активную
версию. Пути проверяются на выход за пределы проекта.

`bootstrap/recovery.py` содержит `activate`, `commit`, `recover`. Будущий обновлятор
должен проверять хеши кандидата и владеть блокировкой до вызова `activate`.
Сначала атомарно записывается `.updates/transaction.json`, затем указатель версии.
Незавершённая (`pending`) транзакция возвращает предыдущую версию **до импорта ядра**.
Подтверждённая (`committed`) сохраняет новую. Повторное восстановление безопасно.
Повреждённый указатель/журнал останавливает старт с ошибкой; документы и настройки
не участвуют в переключении версий. Сам bootstrap будущий обновлятор менять не должен.

## Проверки

```text
python -X utf8 -m unittest discover -s tests -v
```

Проверяются готовность и PID, занятый порт, параллельные повторные запуски,
освобождение блокировки после принудительного завершения, сохранность документов,
повреждённые настройки, изоляция экземпляров, авторизация остановки и восстановление
обновлений. Копия проекта в тестах находится в пути с кириллицей, пробелами, `!`,
`[]`, `&` и апострофом, а текущая папка процесса находится вне проекта.
Windows-проверки дополнительно запускают BAT и настоящий цикл сообщений трея;
CI разбирает скрипты парсером Windows PowerShell 5.1. Проверка видимости консоли
и меню возле часов требует ручного запуска в интерактивной Windows.

Служебные переменные `SAKUYA_NO_BROWSER=1` и `SAKUYA_DISABLE_TRAY=1` предназначены
для автоматических проверок. HTTP слушает только `127.0.0.1`; остановка требует
случайный токен из локального файла экземпляра, запросы из браузерных Origin запрещены.
